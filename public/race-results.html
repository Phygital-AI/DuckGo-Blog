计数、时间与缺失值口径
  • API：provider.jsonl 中 status 非 null 的终态记录，一行一请求；包括 499 等非成功终态。GLM 253 行中剔除 2 条 retry_allowed 通知，真实请求 251。
  • 工具：tools.jsonl 一行一次调用；observe = md_observe，动作提交 = md_act（含错误/拒绝）。program 顶层一次，不把内部 segments 或 action_accepted 当成额外工具调用。
  • 主榜统计全日志，包含赛前准备、启动动作与结束后调用。分段仅分配赛内且远离边界的完成记录；赛外和不确定项单独对账。启动动作若在发车前完成，不挪进 CP1。
  • provider.at 与 tools.at 均为完成/记录时间。race_started 在发车调用前采样，monitor 的 UTC − wallSeconds 给出时钟原点上界；以二者夹住实际原点，额外加入 20ms tick 量化 + 2ms 毫秒日志裕量。边界附近无法确定归属的调用不计入任何段；不是精确到 tick 的 API 时间测量。
  • 区间定义 CP(n−1)→CPn，CP0 是发车。通过与跌倒按事件 tick：边界 tick 属于刚完成区间 (前CP,本CP]。下一未通过区间截止终态 tick；后续未到达不填 0。
  • 恢复：不是恢复次数，也不是两次观察之间简单差值。按事件区间及 runtime recoveryTicks 的含完成 tick 规则重建，连续重试取并集；只有与终态累计严格对账的轮次才分段求交，无法对账整轮分段显示 —。主榜始终保留终态恢复累计值。
  • 新 V2 人类原文件解析 events / samples；人类16次fall、21次recovery_started、18次completed与3次人类翻滚中断分别保留，不是AI计数。终态恢复79.82s；事件边界79.50s，不强行分段。
  • Token 规范化使用 usage inputIncludesCache=false 或 totalTokens 的缓存关系识别输入含缓存口径；缺失 usage / 子字段为未知，不填零。空且确定可统计的区间才可为 0。缓存不重复加，reasoning 不重复加到 output。
